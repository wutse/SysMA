# 券商內部系統排程與服務監控站台 — 第二階段功能待辦清單

> **建立日期**: 2026-04-17  
> **來源**: 由 `BrokerageMonitoringPlatform.requirements.md` 第一階段 Out of Scope 項目轉入  
> **用途**: 作為 Phase 2 分析與開發的起始需求清單，各項目於 Phase 2 `/analyze` 前須進一步確認優先順序與細節

---

## Phase 2 候選功能

| #      | 功能項目                                           | 說明 / 背景                                                                                                                                             | 預估影響面                    |
| ------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| P2-001 | **角色權限控管（RBAC）**                           | Phase 1 採無帳號 Session 姓名識別，所有人員具完整操作權限；Phase 2 可依角色（唯讀檢視、操作員、管理員）限制功能存取                                     | 認證層、UI 路由、稽核日誌     |
| P2-002 | **被監控系統動態自我註冊（Dynamic Registration）** | Phase 1 由設定檔或 UI 手動管理系統與元件；Phase 2 允許被監控系統在連線時自動向站台註冊自身 metadata                                                     | ZeroMQ 協定、設定模型、儀表板 |
| P2-003 | **Pull 模式輪詢（主動查詢被監控系統）**            | Phase 1 純 Push 模式，站台被動接收；Phase 2 可支援站台主動向被監控系統查詢狀態（適用無法推送的場景）                                                    | ZeroMQ 拓撲、元件設定         |
| P2-004 | **超過 30 天的長期歸檔與合規報表**                 | Phase 1 資料保留 30 天自動清除；Phase 2 可引入長期歸檔儲存（如獨立 DB / 檔案歸檔）與合規報表匯出                                                        | 資料保留政策、儲存層、報表 UI |
| P2-005 | **排程規則的新增 / 修改（排程管理）**              | Phase 1 僅監控排程執行狀態，不管理排程定義；Phase 2 可提供排程定義的 CRUD 管理，並下推至被監控系統                                                      | 排程管理 UI、指令協定擴充     |
| P2-006 | **SMTP 帳密驗證**                                  | Phase 1 使用公司 Mail Relay 無需帳密；Phase 2 如需支援外部 SMTP 或具驗證需求的 relay，須實作帳密設定                                                    | Email 設定、Secrets 管理      |
| P2-007 | **計畫性維護的自動時段排程**                       | Phase 1 維護模式僅支援手動開啟/關閉；Phase 2 可設定預定維護時間窗口，系統自動進入/退出維護模式                                                          | 排程器、維護模式邏輯          |
| P2-008 | **ZeroMQ 雙向指令通道與狀態控制**                  | Phase 1 僅於站台提供前端手動覆寫項目狀態；Phase 2 實作站台透過 ZeroMQ ROUTER/DEALER 發送執行指令（觸發、暫停、啟停）至被監控服務及指令狀態追蹤/重試機制 | 指令通道、稽核日誌、UI        |
| P2-009 | **共用上游依賴相關性分析**                         | Phase 1 多元件共用上游依賴同時 Lost 為預期行為，各自觸發告警不做相關性分析；Phase 2 可引入依賴圖建模，識別根因並抑制衍生告警                            | 拓撲模型、告警去重邏輯        |

---

## 備註

- 各項目進入 Phase 2 開發前，需重新執行 `/analyze` 流程以確認細節需求。  
- 優先順序由業務方依營運需求決定，建議先處理 **P2-001（RBAC）** 與 **P2-007（自動維護時段）**，兩者對日常維運影響最大。
- P2-009 涉及架構層面的拓撲建模，建議作為獨立子系統評估。
